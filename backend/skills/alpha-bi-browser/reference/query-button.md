# 查询按钮组件（Query Button）

## 适用范围

- 页面存在“查询”主按钮
- 点击后触发表格刷新或图表重算

## 标准操作流程

1. 在完成筛选并校验通过后，锁定目标区块。
2. `browser_snapshot` 定位该区块内“查询”按钮 ref。
3. 点击“查询”按钮。
4. `browser_wait` 等待结果刷新（默认 1~2 秒）。
5. 再 snapshot 校验结果区域已更新。
6. 校验通过后禁止重复点击同一“查询”按钮。

## 定位优先级

1. 按钮文本“查询”
2. 主按钮样式（如 primary）
3. 筛选区内就近按钮

## 组件元素特征（可固定）

以下特征可用于识别“查询”动作按钮：

- `ant-btn` + `ant-btn-primary` 组合样式
- 按钮文本与当前筛选区同容器关系
- 按钮触发后结果区（表格/图表）出现加载或数据变化信号

注意：优先固定“按钮语义 + 样式 + 区块关系”，避免写死某页唯一 DOM 路径。

## 备用策略

- 若存在多个“查询”，优先点击与当前筛选区同一容器内的按钮。
- 若按钮被遮挡，先关闭下拉/弹层再点击。
- 若结果未更新，先检查筛选值是否确已生效，再决定是否重查。

## 失败信号与恢复

- 失败信号：点击后无刷新、数据未变化、按钮不可用。
- 恢复步骤：
  - 二次 snapshot 确认按钮状态
  - 重新执行最后一步筛选后再查询
  - 避免连续快速点击查询，重试前至少等待一次渲染周期
  - 必要时提示用户检查筛选条件是否合法

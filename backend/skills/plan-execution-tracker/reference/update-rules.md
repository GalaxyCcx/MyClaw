# Update Rules

## 每步更新最小规则

1. 先读后写：更新前必须先 `read_file(plan_path)`。
2. 单步推进：每轮只推进一个步骤状态，避免批量跳步。
3. 必有依据：状态从 `in_progress -> done` 时，必须写明完成证据（如页面值、文件产物、校验结果）。
4. 失败可追溯：若失败，写入 `blocked` 与原因，不得静默重试超过 2 次。

## 计划修订规则

1. 修订必须在 `Plan Revisions` 记录：
   - 时间
   - 触发原因
   - 变更内容
2. 已完成步骤默认不可回退，除非用户明确要求重做。
3. 新增步骤默认 `pending`，并明确其前置依赖。

## 收尾规则

1. 汇总前检查：
   - 无 `in_progress`
   - 无 `blocked`
2. 先输出阶段总结，再删除临时文件。
3. 删除失败时必须提示用户文件路径并给出人工清理建议。
